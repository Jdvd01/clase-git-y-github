Flujo completo de Git y GitHub

Esta secuencia resume el recorrido habitual para trabajar con un proyecto y publicarlo o compartirlo en GitHub.

Paso a paso

  1. 1. Crear o clonar el repositorio

    Empiezas con un proyecto nuevo o descargas uno ya existente a tu equipo.

  2. 2. Editar archivos

    Realizas cambios en HTML, CSS, JS u otros archivos del proyecto.

  3. 3. Preparar cambios

    Usas git add para indicar que archivos quieres incluir en el proximo commit.

  4. 4. Guardar con commit

    Usas git commit -m con un mensaje corto y descriptivo.

  5. 5. Sincronizar con GitHub

    Usas git push para subir cambios y git pull para traer actualizaciones.

  6. 6. Compartir o revisar

    Desde GitHub puedes abrir pull requests, revisar codigo o publicar con GitHub Pages.

Comandos minimos para recordar

git status revisa el estado del repositorio.

git add . prepara cambios para commit.

git commit -m "mensaje" guarda un punto del historial.

git push sube cambios al remoto.

git pull descarga cambios del remoto.

Buenas y malas practicas en mensajes de commit

Un mensaje de commit debe explicar que cambio se hizo. Eso facilita revisar, depurar y entender el historial del proyecto con el paso del tiempo.

Buenos mensajes de commit

  • ✓ Anado formulario de contacto
  • ✓ Corrijo error en menu movil
  • ✓ Primera version del layout

Malos mensajes de commit

  • ✗ cambios
  • ✗ arreglo cosas
  • ✗ asdfgh

Mensaje final para clase

El objetivo no es memorizar todos los comandos a la vez, sino entender el orden del flujo y practicarlo hasta que se vuelva natural.
